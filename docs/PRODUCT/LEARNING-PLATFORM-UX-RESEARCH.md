# Learning platform UX research

Internal product research for The AI Rishi learner experience. Not a public page. Not a curriculum. Do not copy any product wholesale.

**Date:** 2026-09-20
**Scope:** Public learner UX on theairishi.com (DevOps Engineer Mastery, 120 days, local-first, no accounts).
**Privacy:** This document must not describe private authoring paths, private repository URLs, or author-only files as learner destinations. The website is the front door.

---

## 1. Methodology

This is a structured product-UX review, not a market survey and not a claim of original ethnography.

**How products were reviewed**

1. Direct knowledge of the live product surfaces (first visit, path, lesson, practice, completion, search, mobile).
2. Public documentation, help centers, and product blogs where they state UX intent (Microsoft Learn “My Learning,” The Odin Project FAQ, Stripe Docs, MDN, web.dev).
3. Independent UX writing on online learning (Baymard Institute’s Online Learning benchmark covering marketplace and cohort products; widely reported Codecademy / Duolingo onboarding writing).
4. Pattern extraction: what a learner can *do in the first two minutes*, how progress is named, how a lesson is structured, what happens at the end of a unit.

**What this is not**

- Not a ranking of “best LMS 2026.”
- Not fabricated retention percentages. Where a number is not sourced, it is omitted.
- Not a request to become Duolingo, Udemy, or Linear.
- Not a visual redesign brief.

**How findings were selected for The AI Rishi**

Keep a pattern only if it helps a serious engineer:

- know where they are
- know what to do today
- practice on a real system
- prove the day
- continue tomorrow

Reject a pattern if it requires accounts, streaks, fake social proof, marketplace clutter, or a second brand language.

## 3. Recurring successful patterns

These showed up across *unrelated* products. That is the point.

### 3.1 The next action is named in the learner’s language

- Microsoft Learn: **Resume** + state (Not started / In progress / Completed).
- The Odin Project / freeCodeCamp: **Start here**, then the next unchecked item.
- LeetCode / SQLBolt / A Tour of Go: **Next** is a control, not a paragraph.
- Linear / Superhuman: the primary button is the current work.

Implication: “Start Day 1” and “Continue Day 3” beat “Explore” and “Resume reading.”

### 3.2 A map exists before a lesson

- roadmap.sh, Microsoft Learn learning paths, KodeKloud / TryHackMe learning paths, CS50’s syllabus, The Odin Project Foundations.
- The map shows what is available vs planned. Udemy and LinkedIn Learning often fail this.

Implication: `/learn` must be a command center for the 120-day map, not a blog index.

### 3.3 A lesson answers five questions in the first screen

Observed in HashiCorp Tutorials, DigitalOcean, Apple Developer Tutorials, web.dev, Microsoft Learn units, Brilliant:

1. What is this.
2. Why it matters.
3. What you will be able to do.
4. How long it takes.
5. What to click.

Implication: Day pages need a lesson header with outcomes and time, not only a title and a “min read.”

### 3.4 Practice is a first-class region, not an afterthought

- Codecademy, Scrimba, Exercism, TryHackMe, OverTheWire, Frontend Mentor: you cannot finish without doing.
- MasterClass, LinkedIn Learning, many Udemy pages: you can “complete” by watching.

Implication: completion is an explicit learner action after practice, never an intersection-observer.

### 3.5 Completion is a state with a next unit

- Microsoft Learn module end: check + next learning unit.
- Duolingo / Brilliant: end-of-lesson summary of what you just did, then next.
- Advent of Code: day complete, see you tomorrow — without punishing you for missing a day.

Implication: Day N complete should list the outcomes and offer Day N+1, or an honest wait if unpublished.

### 3.6 Beginners and experts share one path

- React docs: Learn vs Reference.
- The Odin Project: you may skip Foundations only if you can do the work.
- TryHackMe: same room, optional writeup.
- MDN: skip to syntax.

Implication: “Already know this? Jump to practice.” Do not fork the curriculum.

### 3.7 Local or optional identity

- The Odin Project: no signup required.
- Obsidian / Anki: local state is enough.
- GitHub Skills: GitHub identity is the tool, not the LMS.

Implication: versioned localStorage is the correct v1. Accounts would be a product change, not a UX patch.

### 3.8 Search understands the learner’s words

- Stripe Docs, MDN, Tailwind, GitHub Docs: query “day 1 shell” should not require exact slug `day-01`.
- Marketplace search (Udemy) optimizes for course shopping, not continuation.

Implication: search should surface **Day 1 — Shell**, **Guide — …**, not file names.

### 3.9 Visual system is quiet

- Stripe, Linear, Laracasts, Frontend Masters, Cloudflare docs: type, hairline, one accent.
- Duolingo, DataCamp, Uxcel, SoloLearn: playful color as personality.

Implication: keep cream / ink / gold. Distinguish exercise kinds with kickers, not rainbow cards.

## 4. Recurring UX problems (anti-patterns)

1. **Catalog as homepage.** Udemy, LinkedIn Learning, Skillshare. The learner shops instead of starting.
2. **Video equals completion.** Watching is not operating a shell.
3. **Fake progress.** Position-in-list bars (“lesson 1 of 3 = 33%”) that ignore whether anything was finished.
4. **Streak shame.** Duolingo / DataCamp. Punishes adults who work in incidents.
5. **Points, leagues, badges without evidence.** Treehouse, Codewars rank identity.
6. **Forced signup before first value.** edX, many Coursera flows, most “My Learning” walls.
7. **Dashboard of nothing.** Codecademy’s own research commentary has noted practice is underused when the dashboard is a wall of modules.
8. **Long lessons with no outcomes.** MIT OCW is honest about this (it is a course dump). A product cannot be.
9. **Next = related marketing.** “You might also like.” Kills program gravity.
10. **Social as the primary path.** Creator sites that lead Instagram → YouTube → newsletter. Fine for media; wrong for a 120-day program.
11. **Childish illustration language** on content for working engineers (Grasshopper, some SoloLearn).
12. **Unpublished content as empty articles.** A 404 or a planned row is better than a stub.
13. **Inconsistent lesson shape.** Every Udemy instructor invents a structure. Cognitive load resets daily.
14. **Search that leaks internals.** File paths, repo names, author notes.
15. **Mobile afterthought.** Code blocks that overflow, sticky bars that eat the viewport, 32px tap targets.

## 6. Patterns explicitly rejected

| Pattern | Why rejected |
| --- | --- |
| Accounts / cloud sync | Out of scope. Local-first is intentional. |
| Streaks, hearts, leagues | Anti-adult, anti-incident-worker. Advent of Code shows daily units can exist without shame. |
| XP, points, leaderboards | We have no community size to show honestly; scores without evidence are theater. |
| Marketplace / ratings / “4.8 stars” | We are one program, not a catalog of instructors. |
| Fake learner counts, testimonials, hiring partners | Trust comes from the work. Invented proof destroys it. |
| Forcing Instagram / Telegram in the primary loop | Community is secondary. Learn → practice → complete → continue. |
| Childish mascots, confetti, giant lottie | Audience includes senior engineers. |
| Auto-complete on scroll | Opening a day is not finishing it. |
| Separate beginner curriculum | Maintenance cost and split identity. Skip links instead. |
| Replacing the brand | Ink, cream, gold, serif already match Linear/Stripe-level restraint. |
| Turning lessons into 12 card types | Markdown must stay writable. Kickers on existing H2s only. |
| Public GitHub as the classroom | The website is the classroom. Private authoring stays private. |
| Future AI / Agentic AI surfaces | No real public content yet. Do not tease empty programs. |

## 7. What The AI Rishi already does better

Relative to a typical course site, the current product already has:

- A **real 120-day map** with planned titles (not empty posts).
- **Published vs planned** honesty.
- Editorial visual identity (not a purple SaaS template).
- On-site **Starting Assessment** for Day 1 (baseline before worshipping tools).
- Lesson rhythm already in the markdown: why, words, practise, production, AI review, interview kill, definition of done.
- **No account wall.**
- Keyboard next/previous.
- A privacy boundary: learners use the site, not an authoring repository.

These are assets. The upgrade should amplify them, not replace them.

## 8. What the current site is missing (from the audit)

See also the product spec. The research maps onto these gaps:

1. **Homepage and header always say Start Day 1** even after progress.
2. **Continue-learning hides until a lesson is completed** — a learner who starts Day 1 and leaves has no resume.
3. **Progress bar in the lesson header is positional** (lesson 1 of 3 in a stage), not completion of 120.
4. **`/learn` is a brochure + list**, not a command center with  n / 120 and a current day.
5. **No structured outcomes** in frontmatter; the header cannot say “you should be able to.”
6. **Reading time ≠ estimated work time.**
7. **Completion is “Finished reading?”** — the wrong verb for a practice day.
8. **nextSlug is unused**; completing Day 1 does not offer Day 2 as a state.
9. **No wait state** for the next unpublished day (the nav currently can claim “course completed”).
10. **Lesson H2s are typographically equal** — practise does not look like practise.
11. **No skip-to-practice** for people who already know PATH.
12. **Search type is “Lesson”** rather than “Day 1.”
13. **Mobile lesson chrome** stacks a sticky header, a reading bar, and a floating syllabus button — easy to over-chrome if we add a fat sticky nav.

Largest learner-experience improvements, in order:

1. Honest continue +  n / 120.
2. `/learn` as command center.
3. Day header with outcomes, time, start/skip.
4. Completion as a gate with next day.
5. Visual rhythm on existing headings.

## 9. Architecture implications

- Progress must be **pure functions + a versioned localStorage document**, so it can be tested in Node without a browser and swapped later. No Redux.
- Continue-learning must take a **serialized program catalog** (published flag per day). Client components cannot import `lib/lessons.ts` (filesystem).
- Denominator is **program.days.length (120)**, not “all markdown lessons on the site” (archive AI lessons must not inflate the bar).
- Heading → semantic kind is a **renderer concern**. Authors keep writing `## Practise`.
- Outcomes live in **frontmatter**, 3–5 strings derived from the actual day, required for program days.
- Do not reintroduce runtime filesystem reads. Do not put private repository URLs in client bundles.
- Sticky lesson nav must be **one compact bar**, with `scroll-margin` on headings, `env(safe-area-inset-bottom)` on mobile, and `prefers-reduced-motion`.

## 10. Prioritized recommendations

1. Versioned local progress: started, completed, lastVisited, completedAt.

## 12. How the research changed The AI Rishi

The 112-product review is not a bibliography. These are the patterns that actually moved pixels.

| Research pattern | The AI Rishi implementation | Why we chose it |
| --- | --- | --- |
| Linear-style command-center clarity | `/learn` is a dashboard: live `n / 120`, current-work card, dense published-day list, map. Homepage first viewport is a product stage, not a manifesto. | The previous homepage still looked like a publication. Linear’s lesson is: the next object is the UI. |
| Microsoft Learn resume / state | `SmartCta` + `CurrentWorkCard` compute Start / Continue / wait from versioned local progress. SSR defaults to Start Day 1; the client hydrates the real state. | “Resume” is a named verb. We do not hide continue until a day is completed. |
| roadmap.sh map-as-product | `JourneyMap`: 11 phase bands, 120 day-dots, complete / now / available / planned. Current phase has a gold spine. | The 120-day path has to be glanceable. Cards hid the path. |
| Apple / web.dev calm hierarchy | Tighter chrome (48px header), serif only on titles, sans for body, mono for meta. Homepage close CTA is a panel, not a poster. | Premium does not mean huge type everywhere. |
| Stripe / MDN information scent | Lesson blocks labelled Why / Learn / Predict / Practice / Evidence / Break / Fix / Verify / AI review / Interview / Gate. Kickers are mono, not badges. | You should know what kind of work a section is before reading it. |
| KodeKloud / Killercoda practice-first | Practice, break, and fix blocks use the gold rail and wash. Jump to practice is a first-class control on the contract header. | The day is not a lecture. Practice has to look like practice. |
| GitHub Skills / A Tour of Go immediate action | First viewport: program name + full-width Start Day 1 (or Continue) + the current day. No quiz wall, no catalog. | Time-to-first-keystroke is the onboarding. |
| VS Code workspace feeling | `LessonWorkspaceChrome` + `DayRail` + panelled sections. Reading progress is a 2px gold bar. Code blocks keep a copy header. | An engineer should feel they are in a tool, not a blog CMS. |
| Brilliant progressive reveal | Predict is its own kind (circuit rail) before Practice. We do not paginate the whole day into 12 screens — that would fight long technical notes. | Prediction matters; carousel-lessons do not fit a 45-minute shell day. |
| Frontend Mentor / Exercism proof | `DayCompletion` is a gate: outcomes, explicit Mark complete, next published day or wait. Scroll does not complete. | Evidence is the work. A checkbox without a definition of done is theater. |
| Readwise / Reader resume | `lastVisited` wins if that day is incomplete; otherwise first incomplete published day; unpublished days are skipped, never linked. | Returning to the exact day is the whole returning-learner loop. |

Patterns we still refuse, after the redesign: accounts, streaks, XP, marketplace ratings, fake learner counts, Instagram-first navigation, confetti, public GitHub as the classroom, and the forbidden slogan that `validate.js` already blocks.
